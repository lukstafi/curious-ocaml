# Proposal: Fix broken test suite: Curious-OCaml

**Task**: task-3c984849
**Title**: Fix broken test suite: Curious-OCaml

## Goal

Restore `dune runtest` to a passing state by installing the three missing opam packages (`bogue`, `lwd`, `incremental`) that are declared as formal project dependencies in `curious.opam` but are not present in the current opam switch.

## Acceptance Criteria

- `opam install bogue lwd incremental` succeeds (or the packages are already installed).
- `dune runtest` exits with code 0, with no `No such package: bogue`, `No such package: lwd`, or `No such package: incremental` errors.
- No changes are made to `chapter6/prelude.ml`, `chapter10/prelude.ml`, or any `README.md` file.
- The `chapter10` executable (`dune build chapter10/chapter10.exe` or equivalent) still links successfully against `bogue`, `lwd`, and `incremental`.

## Context

`curious.opam` (generated from `dune-project`) already lists `bogue`, `lwd`, and `incremental` as formal dependencies:

```
depends: [
  ...
  "bogue"
  "lwd"
  "incremental"
  ...
]
```

These packages are available in the opam repository but NOT installed in the current `default` switch (OCaml 5.4.1). As a result, two chapter preludes fail when mdx evaluates them:

- `chapter6/prelude.ml` line 3: `#require "bogue";;`
- `chapter10/prelude.ml` lines 1–3: `#require "bogue";;`, `#require "lwd";;`, `#require "incremental";;`

**Why Option B (removing requires) is NOT the right fix:**

Investigation shows the chapter6 bogue block (around line 943 of `chapter6/README.md`) is tagged `env=ch6` but NOT `skip` — it will execute during mdx tests and genuinely uses `Bogue` API. Removing the `#require` would cause a different failure (unbound module `Bogue`).

The `chapter10` situation is even clearer: `chapter10/dune` has an `(executable ...)` stanza that links against `bogue lwd incremental`, and the chapter10 README contains multiple non-skipped blocks using `lwd` and `incremental` APIs. These packages are load-bearing for the chapter.

**Why Option A (install packages) is correct:**

The packages are explicitly listed in `curious.opam`. The project intends them to be installed. Installing them is the correct alignment with the project's declared dependency contract.

**SDL2 system dependency note:**

`bogue` requires SDL2 system libraries. On macOS this is typically available via Homebrew (`brew install sdl2`). If SDL2 is missing, `opam install bogue` will fail with a system dependency error. In that case, install SDL2 first:
```
brew install sdl2
opam install bogue lwd incremental
```

## Approach

1. Verify SDL2 is available: `brew list sdl2` or `sdl2-config --version`
2. If missing: `brew install sdl2`
3. Install OCaml packages: `opam install bogue lwd incremental`
4. Verify: `cd /Users/lukstafi/curious-ocaml && dune runtest`

No source file changes are required. This is an environment setup task.
